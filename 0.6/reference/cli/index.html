    aiculator debug¶

    Debugging tools: verbosity levels, and changing them on a running server

    aiculator debug

    aiculator debug levels¶

    Explain what each verbosity level shows

    aiculator debug levels

    aiculator debug verbosity¶

    Show or change a running server's verbosity, with no restart

    Changes take effect at once. Use --for, so that a debugging session cannot leave the server logging at a high level by accident. The previous level then comes back by itself.

    aiculator debug verbosity [LEVEL] [flags]

    Examples

      aiculator debug verbosity                     show the current level
  aiculator debug verbosity 5 --for 10m         trace for ten minutes
  aiculator debug verbosity --vmodule engine=5 --for 5m
  aiculator debug verbosity 2                   set it for good

    Flags

          --for duration     go back to the previous level after this long
      --vmodule string   levels per component, such as engine=5

    Launch an ACP harness and feed it tasks (token in SWARM_TOKEN)

    Flags

          --agent string         agent name, for review notes (default "driver")
      --harness string       harness id, from aiculator harness

      --max-tasks int        stop after this many tasks; 0 means no limit
      --sandbox string       sandbox: auto, seatbelt, bwrap, docker or none (default "auto")

    aiculator export¶

    Write tasks or other data to a file: JSON, YAML, CSV, TSV, Excel, HTML or Markdown

    Exports what you choose, in the format you choose. Tasks are the default, and JSON is the default format, unless the file name in -o says otherwise.

    Values are always treated as text: HTML is escaped, Excel cells are stored as strings, and in CSV a value that a spreadsheet would run as a formula starts with a quote.

    aiculator export [tasks|agents|usage|flow|realms] [flags]

    Examples

      aiculator export                                   # All tasks, as JSON
  aiculator export -o tasks.xlsx                     # The file name picks the format
  aiculator export --format html -o report.html --state running,review
  aiculator export --fields id,title,labels.team,owner --format csv
  aiculator export --label team=core --sort priority -o core.yaml
  aiculator export --with-meta --fields id,meta.points -o points.csv
  aiculator export --all -o everything.xlsx          # Tasks from every realm
  aiculator export --list-fields                     # What can be selected
  aiculator export realms --format md

    Flags

          --all                 tasks from every running realm, with a realm column
      --fields strings      what to include, such as id,title,labels.team; see --list-fields
      --format string       json, yaml, csv, tsv, xlsx, html or md; from the file name, or json
      --label stringArray   only with this label, as name=value
      --limit int           stop after this many rows
      --list-fields         list what can be selected, and write nothing
  -o, --output string       file to write; standard output if empty
      --sort string         sort by this field; -field for descending
      --state strings       only these states, such as running,review
      --where stringArray   only where a field has this value, as field=value
      --with-meta           add each task's properties, as meta.NAME; costs one request per task

    aiculator import¶

    Load tasks once from a configured source, such as Jira, Notion or a spreadsheet

    Reads a source named in .agents/sources.yaml, once, and creates a task for each item. Importing again is safe: an item that was imported before is left alone, or brought up to date with --update.

    aiculator import SOURCE [flags]

    Flags

          --config string   sources file; .agents/sources.yaml if empty
      --dry-run         show what would be imported, and change nothing
      --limit int       stop after this many items; 0 means all
      --query string    use this query instead of the configured one: JQL for Jira, a JSON filter for Notion
      --update          bring items that were imported before up to date

    aiculator init¶

    Set up this machine, step by step: harnesses, skills and MCP config

    Asks what you want, then does it. By default this sets up the whole machine: the swarm's skills go where each harness reads them for every project, so that afterwards aiculator join only has to start a server in a project. This needs no git repository and starts no server.

    With --scoped it sets up this project alone, which also offers to start the server, and to create the git repository the swarm needs.

    Nothing is written until the last question is answered, so backing out with Ctrl-C changes nothing. Running it again is safe, and keeps what is already there.

    For a script, --yes takes every default, and flags answer single questions.

    aiculator init [flags]

    Flags

          --all-harnesses    also offer harnesses that were not found on this machine
      --dry-run          say what would be done, and do nothing
      --harness string   set these up without asking: installed, all, or comma-separated ids
      --mcp              add MCP config without asking
      --no-mcp           do not add MCP config
      --no-skills        do not install the skills
      --no-start         do not start the server, with --scoped
      --planner          also allow these sessions to plan
      --sandbox string   sandbox for the server: auto, seatbelt, bwrap, docker or none (default "auto")
      --scoped           set up this project only, rather than the whole machine
      --tier int         tier for MCP sessions: 1 standard, 2 advanced, 3 ultra (default 1)
  -y, --yes              take every default and ask nothing

    aiculator join¶

    Connect installed harnesses to the swarm: server, skills and MCP config

    Sets a project up so any harness can join the swarm, including one already open.

    It starts the server, and works on its own on a machine with nothing set up: it installs the bundled skills into .agents/skills, links them to harnesses that need it, and registers the MCP bridge. Anything a harness can already find is left alone, at either level, so after aiculator init it only has to start the server. No secrets are written.

    aiculator join [flags]

    Flags

          --harness string   installed, all, or comma-separated ids (default "installed")
      --no-start         do not start the server
      --planner          also allow these sessions to plan
      --sandbox string   sandbox for the server: auto, seatbelt, bwrap, docker or none (default "auto")
      --tier int         tier: 1 standard, 2 advanced, 3 ultra (default 1)

    aiculator mcp add¶

    Add the swarm's MCP server, or any server, to a harness's config

    aiculator mcp add [--harness TARGET] [--name NAME -- COMMAND ARGS...] [flags]

    Flags

          --dry-run           show what would be written and change nothing
      --env stringArray   environment variable for a custom server, as KEY=VALUE; stored in plain text

      --name string       server name (default "swarm")
      --planner           allow the swarm's own server to plan
      --tier int          tier for the swarm's own server (default 1)

    aiculator parallel¶

    Work out what subagents can do at the same time in one working tree

    Worktrees keep tasks apart. This is the level below: one task split among subagents in one checkout. Give it the jobs and what each will change, and it says what can safely run at once. Jobs share a wave only if their claims cannot overlap, and a job that claims nothing runs alone.

    This needs no server, and it does not touch the swarm's state.

    aiculator parallel

    aiculator parallel plan¶

    Plan jobs into waves that cannot conflict

    Reads jobs as YAML or JSON. A claim is a file or a directory ending in /. With symbol granularity it can also be file#symbol or file:10-40. Reads are what a job relies on staying the same while it works.

    Granularity is how finely claims are compared. The default, auto, uses the coarser of dir and file that loses no parallelism, and it treats file#symbol as the whole file. To let two jobs share one file, ask for symbol. Their claims are then checked against the file, but nothing can stop a subagent straying, and two in one file can overwrite each other.

    aiculator parallel plan [flags]

    Examples

      aiculator parallel plan --file jobs.yaml -o plan.json
  cat jobs.yaml | aiculator parallel plan --file - --max 3

  # jobs.yaml
  jobs:
    - id: api
      touches: [internal/api/users.go]
    - id: docs
      touches: [docs/users.md]
      reads: [internal/api/users.go]
    - id: format
      exclusive: true
      deps: [api, docs]

    Flags

          --file string          the jobs, as YAML or JSON; - for standard input
      --granularity string   dir, file, symbol, repo or auto (default "auto")
      --json                 print the plan as JSON
      --max int              most subagents at once (default 4)
  -o, --output string        save the plan, for verify

    aiculator plugin¶

    List plugins, both compiled in and on PATH

    Plugins compiled into this binary add commands, server routes and event handlers. Build one in with a blank import in cmd/aiculator; the web dashboard is one, and go build -tags noweb leaves it out.

    Any program on PATH named aiculator-NAME also runs as aiculator NAME.

    aiculator plugin

    aiculator realm¶

    See and name the projects on this machine that use the swarm

    A realm is one project, with its own server and its own store. A project becomes one when its server starts. Realms never share tasks or tokens, so trouble in one stays there.

    Act on one from any folder with --realm NAME, such as: aiculator --realm shop task ls See them all with: aiculator top --all, or aiculator web --all

    aiculator realm

    aiculator serve¶

    aiculator skill¶

    Manage skills in one place: .agents/skills

    Skills live in .agents/skills. Installing puts them where each harness looks: harnesses that scan .agents/skills need nothing, and the others get a link. Skills in .agent/skills are picked up too. An edit in one place reaches every harness.

    Patterns use * for anything, ? for one character and [abc] for a set. Quote any pattern with a wildcard: an unquoted * alone also works, but zsh stops at an unmatched *-sth.

    aiculator skill [--install PATTERN...] [flags]

    Examples

      aiculator skill --install '*'                  all skills, to every installed harness
  aiculator skill --install 'swarm-*' 'lint-?'   by pattern
  aiculator skill --install '*-tool' --global    into ~/.agents/skills and home directories
  aiculator skill --install '*' --harness all    every supported harness, installed or not
  aiculator skill --install x --harness claude,pi
  aiculator skill --install x --path ./vendor/skills --harness none
  aiculator skill --install x --source ~/my-skills
  aiculator skill --list
  aiculator skill --lint
  aiculator skill --new my-skill --description "..."
  aiculator skill --uninstall 'swarm-*' --purge

    Flags

          --copy                 copy instead of linking, for tools that do not follow links
      --description string   description for --new
      --force                refresh bundled skills and replace links; your own directories are never replaced
      --global               use ~/.agents/skills and home directories
      --harness string       installed, all, none, or comma-separated ids (default "installed")
      --install strings      install skills matching these patterns
      --lint                 check skills against the Agent Skills spec
      --list                 list skills
      --new string           create a skill with full metadata
      --path strings         also install to this directory
      --purge                with --uninstall, also delete from .agents/skills
      --source strings       also read skills from this directory
      --uninstall strings    remove skills matching these patterns from harnesses

    aiculator template¶

    Render reusable instruction templates into skills

    Templates live in .agents/templates; .agent/templates and .agent/template also work. They use Jinja2 and MDX-style components, and render into skills that install exactly as aiculator skill --install does.

    Bundled components: Directive, Anchor, Subagents, Backoff, OutputFormat, Flow, Step, Note, Toc. Add or replace one by creating components/NAME.md in a template directory.

    These produce instructions for a model. A model can still ignore text, so anything that must hold needs a real check, such as a task's --check command.

    aiculator template [--install PATTERN...] [flags]

    Examples

      aiculator template --list
  aiculator template --new my-rules
  aiculator template --render agent-discipline --set retries=5
  aiculator template --install '*'
  aiculator template --install 'agent-*' --global --set timeout=300s
  aiculator template --install x --per-harness       a separate copy per harness
  aiculator template --install x --path ./vendor/skills --harness none
  aiculator template --check                         fail if a rendered skill is stale

    Flags

          --check             fail if a rendered skill no longer matches its template
      --copy              copy instead of linking
      --for string        with --render, render as this harness
      --force             replace links; your own directories are never replaced
      --global            use ~/.agents and home directories

      --list              list templates

      --path strings      also install to this directory
      --per-harness       render a separate copy into each harness's own directory
      --render string     print one rendered template; writes nothing

    aiculator top¶

    Live terminal dashboard: flow, throughput, latency, jitter, probes, liveness and usage

    A live view of the swarm. Keys: 1-5 or tab switch views, arrows or j and k scroll, p pauses, q quits.

    Without a terminal, such as in a pipe, it prints one frame and exits. Rates reset when the server restarts. Task states and usage totals do not.

    aiculator top [flags]

    Flags

          --all                 show every realm on this machine: 1 realms, 2 tasks, 3 agents
      --color               with --once: keep color even in a pipe
      --interval duration   how often to refresh (default 1s)
      --json                print the raw snapshot as JSON and exit
      --no-color            no color; NO_COLOR also works
      --once                print one frame and exit
      --view string         with --once: overview, tasks, agents, flow or usage (default "overview")
      --width int           with --once: width in columns
