    aiculator debug verbosity¶

    Show or change a running server's verbosity, with no restart

    Changes take effect at once. Use --for, so that a debugging session cannot leave the server logging at a high level by accident. The previous level then comes back by itself.

    aiculator debug verbosity [LEVEL] [flags]

    Examples

      aiculator debug verbosity                     show the current level
  aiculator debug verbosity 5 --for 10m         trace for ten minutes
  aiculator debug verbosity --vmodule engine=5 --for 5m
  aiculator debug verbosity 2                   set it for good

    Flags

          --for duration     go back to the previous level after this long
      --vmodule string   levels per component, such as engine=5

    aiculator join¶

    Connect installed harnesses to the swarm: server, skills and MCP config

    Sets a project up so any harness can join the swarm, including one already open.

    It starts the server, installs the bundled skills into .agents/skills, links them to harnesses that need it, and registers the MCP bridge. No secrets are written.

    aiculator join [flags]

    Flags

          --harness string   installed, all, or comma-separated ids (default "installed")
      --no-start         do not start the server
      --planner          also allow these sessions to plan
      --sandbox string   sandbox for the server: auto, seatbelt, bwrap, docker or none (default "auto")
      --tier int         tier: 1 standard, 2 advanced, 3 ultra (default 1)

    aiculator mcp¶

    Serve the swarm's MCP tools over stdio (--auto, or a token in SWARM_TOKEN)

    aiculator mcp [flags]

    Flags

          --agent string     agent name; generated if empty
      --auto             find the local server and get a token by itself
      --harness string   harness id, used in the agent's name

      --url string       server URL; --auto finds it (default "http://127.0.0.1:7777")

    aiculator mcp add¶

    Add the swarm's MCP server, or any server, to a harness's config

    aiculator mcp add [--harness TARGET] [--name NAME -- COMMAND ARGS...] [flags]

    Examples

      aiculator mcp add                               every installed harness
  aiculator mcp add --harness opencode --tier 2
  aiculator mcp add --harness claude,cursor --global
  aiculator mcp add --harness ~/.local/bin/opencode   found from the executable
  aiculator mcp add --harness ./custom/mcp.json       a config file; format inferred
  aiculator mcp add --name docs --harness claude -- npx -y docs-server

    Flags

          --dry-run           show what would be written and change nothing
      --env stringArray   environment variable for a custom server, as KEY=VALUE; stored in plain text
      --format string     for a config path: mcpServers-json, opencode-json or codex-toml; inferred if empty
      --global            use the harness's user-level config
      --harness string    auto, all, ids, a harness executable, or a config file path (default "auto")
      --name string       server name (default "swarm")
      --planner           allow the swarm's own server to plan
      --tier int          tier for the swarm's own server (default 1)

    aiculator plugin¶

    List plugins, both compiled in and on PATH

    Plugins compiled into this binary add commands, server routes and event handlers. Build one in with a blank import in cmd/aiculator; the web dashboard is one, and go build -tags noweb leaves it out.

    Any program on PATH named aiculator-NAME also runs as aiculator NAME.

    aiculator plugin

    aiculator serve¶

    Start the swarm server

    aiculator serve [flags]

    Flags

          --addr string              listen address; port 0 picks a free one (default "127.0.0.1:7777")
      --branch string            branch that receives merged work (default "swarm/integration")
      --exit-grace duration      quiet time before agents are told to exit (default 30s)
      --lease-ttl duration       lease length (default 2m0s)
      --progress-ttl duration    time without file changes before an agent counts as a zombie (default 10m0s)
      --repo string              git repository to work on; empty disables the work layer
      --restart-grace duration   no lease expires this soon after a restart (default 15s)
      --sandbox string           sandbox: auto, seatbelt, bwrap, docker or none (default "auto")
      --sync-always              fsync every write; survives power loss but is slower

    aiculator skill¶

    Manage skills in one place: .agents/skills

    Skills live in .agents/skills. Installing puts them where each harness looks: harnesses that scan .agents/skills need nothing, and the others get a link. Skills in .agent/skills are picked up too. An edit in one place reaches every harness.

    Patterns use * for anything, ? for one character and [abc] for a set. Quote any pattern with a wildcard: an unquoted * alone also works, but zsh stops at an unmatched *-sth.

    aiculator skill [--install PATTERN...] [flags]

    Examples

      aiculator skill --install '*'                  all skills, to every installed harness
  aiculator skill --install 'swarm-*' 'lint-?'   by pattern
  aiculator skill --install '*-tool' --global    into ~/.agents/skills and home directories
  aiculator skill --install '*' --harness all    every supported harness, installed or not
  aiculator skill --install x --harness claude,pi
  aiculator skill --install x --path ./vendor/skills --harness none
  aiculator skill --install x --source ~/my-skills
  aiculator skill --list
  aiculator skill --lint
  aiculator skill --new my-skill --description "..."
  aiculator skill --uninstall 'swarm-*' --purge

    Flags

          --copy                 copy instead of linking, for tools that do not follow links
      --description string   description for --new
      --force                refresh bundled skills and replace links; your own directories are never replaced
      --global               use ~/.agents/skills and home directories
      --harness string       installed, all, none, or comma-separated ids (default "installed")
      --install strings      install skills matching these patterns
      --lint                 check skills against the Agent Skills spec
      --list                 list skills
      --new string           create a skill with full metadata
      --path strings         also install to this directory
      --purge                with --uninstall, also delete from .agents/skills
      --source strings       also read skills from this directory
      --uninstall strings    remove skills matching these patterns from harnesses

    aiculator template¶

    Render reusable instruction templates into skills

    Templates live in .agents/templates; .agent/templates and .agent/template also work. They use Jinja2 and MDX-style components, and render into skills that install exactly as aiculator skill --install does.

    Bundled components: Directive, Anchor, Subagents, Backoff, OutputFormat, Flow, Step, Note, Toc. Add or replace one by creating components/NAME.md in a template directory.

    These produce instructions for a model. A model can still ignore text, so anything that must hold needs a real check, such as a task's --check command.

    aiculator template [--install PATTERN...] [flags]

    Examples

      aiculator template --list
  aiculator template --new my-rules
  aiculator template --render agent-discipline --set retries=5
  aiculator template --install '*'
  aiculator template --install 'agent-*' --global --set timeout=300s
  aiculator template --install x --per-harness       a separate copy per harness
  aiculator template --install x --path ./vendor/skills --harness none
  aiculator template --check                         fail if a rendered skill is stale

    Flags

          --check             fail if a rendered skill no longer matches its template
      --copy              copy instead of linking
      --for string        with --render, render as this harness
      --force             replace links; your own directories are never replaced
      --global            use ~/.agents and home directories
      --harness string    installed, all, none, or comma-separated ids (default "installed")
      --install strings   render and install templates matching these patterns
      --list              list templates
      --new string        create a starter template
      --path strings      also install to this directory
      --per-harness       render a separate copy into each harness's own directory
      --render string     print one rendered template; writes nothing
      --set stringArray   template variable, as KEY=VALUE
      --source strings    also read templates from this directory

    aiculator top¶

    Live terminal dashboard: flow, throughput, latency, jitter, probes, liveness and usage

    A live view of the swarm. Keys: 1-5 or tab switch views, arrows or j and k scroll, p pauses, q quits.

    Without a terminal, such as in a pipe, it prints one frame and exits. Rates reset when the server restarts. Task states and usage totals do not.

    aiculator top [flags]

    Flags

          --color               with --once: keep color even in a pipe
      --interval duration   how often to refresh (default 1s)
      --json                print the raw snapshot as JSON and exit
      --no-color            no color; NO_COLOR also works
      --once                print one frame and exit
      --view string         with --once: overview, tasks, agents, flow or usage (default "overview")
      --width int           with --once: width in columns
